# 03 · 部署手册（30 人可用）

> 适用：管理员 / 维护者
> 最后更新：2026-11-06
> **★ 当前是"本地开发版"，30 人使用前必须完成本文档的三步升级**

---

## 零、两种部署形态

| 形态 | 适用人数 | 数据库 | 缺点 |
|---|---|---|---|
| **A. 开发版**（现在） | 1~5 人 | SQLite | 30 人并发会锁库 |
| **B. 生产版**（30 人必须） | 10~50 人 | PostgreSQL | 需要一台常开的服务器 |

**★★ 30 人必须上 B。**

---

## 一、为什么必须换 PostgreSQL（关键）

```
SQLite 的写锁是【数据库级】的：
  同一时刻只允许一个写者
  → 30 人同时提交任务 → "database is locked"

PostgreSQL 的锁是【行级】的：
  不同行可以同时写
  → 30 人并发没问题
```

**★ SQLite 只适合"读多写少"或"单人"场景。**

---

## 二、部署到内网服务器（推荐方案）

### 硬件要求

```
CPU：2 核以上（树莓派 4B 也行，但推荐 x86）
内存：2GB 以上
硬盘：20GB 以上
系统：Ubuntu 22.04 / Debian 12
网络：和队伍在同一个内网（WiFi 或网线）
```

### 步骤 1 · 装 PostgreSQL

```bash
sudo apt update
sudo apt install -y postgresql postgresql-contrib

# 创建数据库和用户
sudo -u postgres psql <<'SQL'
CREATE DATABASE rm_lab;
CREATE USER rmlab WITH PASSWORD '换成你的强密码';
GRANT ALL PRIVILEGES ON DATABASE rm_lab TO rmlab;
ALTER DATABASE rm_lab OWNER TO rmlab;
SQL
```

### 步骤 2 · 部署后端

```bash
# 在服务器上
cd /opt
sudo git clone <你的仓库地址> JB-RM-Lab-Manager
sudo chown -R $USER:$USER JB-RM-Lab-Manager
cd JB-RM-Lab-Manager/backend

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# ★ 创建 .env（不要用默认值！）
cat > .env <<'ENV'
SECRET_KEY=这里填一个64位随机字符串_用下面的命令生成
DATABASE_URL=postgresql://rmlab:你的密码@localhost:5432/rm_lab
ACCESS_TOKEN_EXPIRE_MINUTES=720
DEFAULT_ADMIN_ID=admin
DEFAULT_ADMIN_PASSWORD=改成你的密码
MAX_UPLOAD_MB=50
ENV

# 生成随机 SECRET_KEY
python3 -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(48))"

# 建表 + 管理员
python -m app.init_db

# 迁移（生产用 alembic）
alembic upgrade head
```

### 步骤 3 · 用 systemd 常驻

```bash
sudo cat > /etc/systemd/system/rmlab-backend.service <<'UNIT'
[Unit]
Description=RM Lab Manager Backend
After=network.target postgresql.service

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/JB-RM-Lab-Manager/backend
Environment="PATH=/opt/JB-RM-Lab-Manager/backend/.venv/bin"
ExecStart=/opt/JB-RM-Lab-Manager/backend/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now rmlab-backend
sudo systemctl status rmlab-backend
```

### 步骤 4 · 前端打包 + Nginx

```bash
cd /opt/JB-RM-Lab-Manager/frontend
npm install
npm run build          # 产物在 dist/

sudo apt install -y nginx
sudo cat > /etc/nginx/sites-available/rmlab <<'NGINX'
server {
    listen 80;
    server_name _;      # 内网直接用 IP

    # 前端静态文件
    root /opt/JB-RM-Lab-Manager/frontend/dist;
    index index.html;

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反代
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 60m;    # ★ 要大于 MAX_UPLOAD_MB
    }

    # 附件下载
    location /static/ {
        proxy_pass http://127.0.0.1:8000;
        client_max_body_size 60m;
    }
}
NGINX

sudo ln -sf /etc/nginx/sites-available/rmlab /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 步骤 5 · 验证

```bash
# 查服务器 IP
hostname -I

# 从另一台电脑访问
curl http://<服务器IP>/api/health
# 浏览器打开 http://<服务器IP>/
```

**★ 30 人访问的地址就是：`http://<服务器IP>/`（不用带端口，Nginx 80 端口）**

## 三、数据库迁移（SQLite → PostgreSQL）

**如果你已经有数据了：**

```bash
# ① 后端切到 SQLite（旧库）
# ② 导出数据
python3 - <<'PY'
import sqlite3, json
c = sqlite3.connect('rm_lab.db')
out = {}
for t in ['users','tasks','submissions','upload_files']:
    cur = c.execute(f'SELECT * FROM {t}')
    cols = [d[0] for d in cur.description]
    out[t] = [dict(zip(cols, r)) for r in cur.fetchall()]
json.dump(out, open('backup.json','w'), ensure_ascii=False, indent=2)
print('已导出', {k: len(v) for k, v in out.items()})
PY

# ③ 切到 PostgreSQL（改 .env）
# ④ 建表
alembic upgrade head

# ⑤ 导入数据
python3 - <<'PY'
# 需要自己写导入脚本（按 models 的字段映射）
# 或直接用 pgloader：
#   pgloader sqlite:///rm_lab.db pgsql://rmlab:密码@localhost/rm_lab
PY
```

**★ 更简单：数据少的话，直接重新录入（30 人 10 分钟）。**

## 四、备份（★ 必须做）

### 自动备份脚本

```bash
cat > /opt/JB-RM-Lab-Manager/backup.sh <<'SH'
#!/bin/bash
BACKUP_DIR=/opt/JB-RM-Lab-Manager/backups
mkdir -p "$BACKUP_DIR"
DATE=$(date +%Y%m%d_%H%M%S)

# 数据库
PGPASSWORD=你的密码 pg_dump -h localhost -U rmlab rm_lab \
  > "$BACKUP_DIR/db_$DATE.sql"

# 附件
tar czf "$BACKUP_DIR/uploads_$DATE.tar.gz" \
  /opt/JB-RM-Lab-Manager/backend/static/uploads/

# 只保留最近 30 天
find "$BACKUP_DIR" -name "*.sql" -mtime +30 -delete
find "$BACKUP_DIR" -name "*.tar.gz" -mtime +30 -delete

echo "备份完成: $DATE"
SH
chmod +x /opt/JB-RM-Lab-Manager/backup.sh

# 每天凌晨 3 点备份
(crontab -l 2>/dev/null; echo "0 3 * * * /opt/JB-RM-Lab-Manager/backup.sh >> /var/log/rmlab-backup.log 2>&1") | crontab -
```

### 手动备份（任何时候）

```bash
/opt/JB-RM-Lab-Manager/backup.sh
```

## 六、日常维护命令

```bash
# 看后端日志
sudo journalctl -u rmlab-backend -f

# 重启后端
sudo systemctl restart rmlab-backend

# 重载 Nginx
sudo systemctl reload nginx

# 查谁在用（在线连接）
sudo -u postgres psql -d rm_lab -c "SELECT pid, usename, state, query_start FROM pg_stat_activity WHERE datname='rm_lab';"

# 数据库大小
sudo -u postgres psql -d rm_lab -c "SELECT pg_size_pretty(pg_database_size('rm_lab'));"
```

## 七、安全清单（上线前逐条打勾）

```
□ SECRET_KEY 已换成 64 位随机串（不是默认值）
□ 默认管理员密码已改（不是 123456）
□ PostgreSQL 密码是强密码
□ 数据库只监听 localhost（不要 0.0.0.0）
□ .env 文件权限 600（chmod 600 .env）
□ 备份任务已配 crontab
□ 防火墙只开放 80（如果不需要 8000 直连）
   sudo ufw allow 80
   sudo ufw enable
□ 后端 --workers 2 以上（并发）
□ Nginx client_max_body_size ≥ MAX_UPLOAD_MB
```

**★ 内网部署不需要 HTTPS，但如果要暴露到公网，必须加（用 certbot）。**

## 八、监控（可选）

```bash
# 简单的健康检查（加到 crontab，异常发邮件/微信）
cat > /opt/JB-RM-Lab-Manager/healthcheck.sh <<'SH'
#!/bin/bash
if ! curl -sf http://127.0.0.1:8000/api/health > /dev/null; then
  echo "[$(date)] 后端挂了！" >> /var/log/rmlab-alert.log
  sudo systemctl restart rmlab-backend
fi
SH
chmod +x /opt/JB-RM-Lab-Manager/healthcheck.sh

(crontab -l 2>/dev/null; echo "*/5 * * * * /opt/JB-RM-Lab-Manager/healthcheck.sh") | crontab -
```
