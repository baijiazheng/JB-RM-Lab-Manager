## 一、★ 已验证的坑（踩过，别再踩）

### 坑 1 · passlib + bcrypt 版本不兼容（★★★ 最坑）

```
现象：
  ValueError: password cannot be longer than 72 bytes,
  truncate manually if necessary

原因：
  passlib 1.7.4 与 bcrypt 4.1+ 不兼容

解决：
  pip install "bcrypt==4.0.1"

已做：
  requirements.txt 里没锁 bcrypt（因为 pip 会拉最新）
  → README 和 docs/03 都写了要手动装 4.0.1
  → ★ 建议以后把 bcrypt==4.0.1 直接写进 requirements.txt
```

### 坑 2 · Alembic 检测不到新表

```
现象：
  alembic revision --autogenerate 生成的脚本是空的

原因：
  新 model 没在 app/models/__init__.py 里 import

解决：
  在 models/__init__.py 里加 from app.models.xxx import Xxx
```

### 坑 3 · 前端 CORS 报错

```
现象：
  Access to XMLHttpRequest blocked by CORS policy

原因：
  后端没启动，或者端口不对（不是 8000）

解决：
  · 确认后端在 127.0.0.1:8000
  · 或者前端 vite.config.js 的 proxy 目标写错了
```

### 坑 4 · 附件上传 413

```
现象：
  Nginx 返回 413 Request Entity Too Large

原因：
  Nginx 的 client_max_body_size 默认 1MB

解决：
  Nginx 配置里加 client_max_body_size 60m;
  （要大于 .env 里的 MAX_UPLOAD_MB）
```

### 坑 5 · uvicorn 改了代码不生效

```
原因：
  启动时没加 --reload

解决：
  uvicorn app.main:app --reload --port 8000
```

### 坑 6 · 前端 404（刷新页面就 404）

```
现象：
  登录后能用，刷新 /admin/users 就 404

原因：
  Nginx 没配 SPA 回退

解决：
  location / { try_files $uri $uri/ /index.html; }
```

### 坑 7 · 数据库锁（30 人必现）

```
现象：
  sqlite3.OperationalError: database is locked

原因：
  SQLite 单写锁

解决：
  ★ 换 PostgreSQL（见 docs/03-部署手册.md）
```

### 坑 8 · 时间显示不对（差 8 小时）

```
现象：
  数据库存的时间比实际少 8 小时

原因：
  datetime.utcnow() 存的是 UTC，前端直接显示没转换

现状：
  ★ 当前版本【没处理时区】—— 所有时间都是 UTC
  → 前端显示的是 UTC 时间，不是北京时间

解决（二选一）：
  A. 前端显示时 +8 小时（简单但 hack）
  B. 数据库改存本地时间（要改所有 datetime.utcnow()）
  C. 用 timezone-aware datetime（最规范，改动最大）

★ 当前选择：先不管（1 小时内的误差可以接受）
★ 如果要修：见下面「待改进」第 1 条
```
